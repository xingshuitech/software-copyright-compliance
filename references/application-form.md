# 申请表逐字段口径

申请表和四类材料必须逐字一致：软件全称、版本号、开发完成日期、编程语言、源程序量、技术特点类别。任何一项改动都要全链同步。

## 2026 年 3 月 15 日新版申请表

依据中国版权保护中心通知与行业协会对照表，出处见 `legal-basis.md`。

- 「主要功能和技术特点」由 200 字以内调整为 500–1300 字。
- 签章页承诺新增「未使用 AI 开发编写代码、撰写文档或生成登记申请材料」。
- 新增经办人签名与身份证号码。
- 建立诚信制度与失信惩戒，虚假材料可能列入失信名单并影响个人征信。

操作要求：

- 签章页由申请人本人按系统当前文本手抄，不代抄、不预填、不改动格式和打印比例。
- 助手起草的功能描述，申请人应逐字核实并按真实开发事实修改确认后再提交。
- 若系统显示的字数或承诺文本与本文不一致，以系统为准。

## 基础字段

| 字段 | 口径 |
|---|---|
| 软件全称 | 与页眉、用户手册封面、鉴别材料完全一致 |
| 软件简称 | 无则留空，不要写「无」 |
| 版本号 | 写登记版本，例如 `V1.0`；不写内部小版本。证书版本号以申请表为准，鉴别材料页眉须一致，有无 `V` 也以申请表为准 |
| 开发完成日期 | 代码最后一次落盘日，不是文档编制日、不是申请日 |
| 发表状态 | 未公开发布选「未发表」；发布日期留空 |
| 著作权人 | 按用户确认的署名方式；只写软件名称时不署个人 |
| 源程序量 | 登记范围内源码物理行数，与鉴别材料统计一致 |

## 运行环境

写环境类型和主版本，不要为了精确超出字数限制。

示例写法（按实际环境替换）：

```text
Node.js 22.x；acorn 8.x、acorn-walk 8.x、astring 1.x
```

精确版本串容易超过申请表 50 字限制。精确版本写进用户手册的环境章节即可，申请表按主版本写，保持与手册一致。

## 编程语言与类别

- 编程语言只勾实际使用的语言。
- 技术特点类别按软件实质选，例如源码保护类工具可选 `信息安全软件`。
- 不要因为使用了 AST 分析就勾 `人工智能软件`。
- 分类说明控制在 100 字以内，写具体处理对象和处理方式。

分类说明示例：

```text
对 JavaScript 源码进行词法与语法分析，按作用域改写标识符，
对字符串常量逐项加密，并插入控制流变换与随机化解包层，
用于源码交付过程中的静态阅读防护。
```

## 开发目的与面向领域

开发目的写「解决什么问题」，不写「推动行业发展」。面向领域写行业代码，不写宽泛口号。

示例：

```text
开发目的：在不改变脚本调用方式的前提下，增加源码交付环节的静态分析成本。
面向领域：信息安全；软件保护；JavaScript 源码交付。
```

## 主要功能和技术特点

该栏通常要求 500–1300 字。按以下顺序写，不空泛铺陈：

1. 输入形式与处理方式：读取 JavaScript 源码，经词法与语法分析生成语法树。
2. 核心处理：作用域感知重命名、字符串逐串加密、控制流调整、噪声插入。
3. 解包层：随机状态规模、取流顺序、校验门限、 Base64 载荷。
4. 工程特性：三档强度、CLI 与工作台、报告输出、目录结构保持不变。
5. 边界：动态求值、外部加载器等场景不承诺覆盖。

可用的措辞：

```text
自研语法树变换管线
逐串独立派生密钥
状态调度与取流形式均为自行设计
解码记忆化
有序校验和
旋转唯一性验证
```

不要写：

```text
原创算法
世界领先
不可破解
百分百兼容
```

## 材料一致性速查

提交前逐项比对：

- 软件名 + 版本：申请表、用户手册页眉、开发记录页眉、代码材料页眉、算法说明页眉。
- 版本号：申请表只写对外版本；源码内部版本常量与构建代号保留在鉴别材料里，不为统一口径改动源码。
- 源程序量：申请表行数 = 鉴别材料收录源码物理行数。
- 开发完成日期：不晚于源码最后修改时间，不等于材料生成时间。
- 技术特点：申请表勾选项 = 算法特色说明展开的内容。
- 语言与环境：申请表 = 用户手册环境章节。
